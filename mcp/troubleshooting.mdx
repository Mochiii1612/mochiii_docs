---
title: "Troubleshooting MCP"
description: "What to do when an MCP server will not start, needs a key, or its tools are not used."
---

A server that fails to start says why; start with `/mcp` (or **⋯ → Customize → MCP** in VS Code), which lists every server and its state, the ones that need you first.

*Describes terminal app 1.6.1 and VS Code extension 1.0.2, which works with terminal app 1.6.1 or later.*

## It will not start

| What you see | What to do |
|---|---|
| A key has no value, with the command that sets it | Run that command, for example `/mcp-server key github GITHUB_TOKEN`. See [Keys and variables](/mcp/keys-and-variables) |
| "it needs Node.js >=24, and this computer has v20.20.2" | Install or update the program it names |
| **Needs uv** or **Needs Docker** on its card | Install `uv` or Docker first |
| It did not start in time | The first start can be slow while `npx` or `uvx` downloads it. Run `/mcp-server check <name> --timeout 60` |
| It is waiting | Agent mode must be on for any tool to run; with it off, an added server is stored and says it is waiting |
| A project's server stays pending | A server from a project's `.mcp.json` does not start until you approve it |

`/mcp-server check [name]` starts one server, or all of them, to see whether they work. In VS Code, use **Check connection** on the server, or **Mochiii: Check MCP Server**.

## Its tools are not used

- The model is shown at most 24 tools at a time, Mochiii's own first. A server with many tools gets only some of them on the menu, and the model reaches the rest with `find_tools`. `/mcp-server` lists the ones left off.
- A model that cannot use tools gets none. See [Local models](/models/local-models).

## A call failed

One failed call no longer takes a server down: a reply over the size limit fails only that call, and a server that stops during a call is restarted once. The model is told what happened.

## Still stuck

The background service's log is in `~/.local/state/mochiii/logs/`; in VS Code, run **Mochiii: Show Daemon Log**. See [Troubleshooting](/troubleshooting).
