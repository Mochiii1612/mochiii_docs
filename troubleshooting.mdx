description: "Fixes for common Mochiii problems: chats that stop saving after an update, code search that is off, models that do not answer, and VS Code notices."
---

Most problems come from mismatched versions, a missing code-search engine, or a model that cannot be reached; each has a fix below.

*Describes terminal app 1.6.1 and VS Code extension 1.0.2, which works with terminal app 1.6.1 or later.*

## I updated one client and chats stopped saving

Mochiii keeps chat memory in one file for every folder on the machine. The first new version to open it upgrades it in place, keeping every chat, and an older version cannot use the upgraded file. The VS Code extension brings its own copy of Mochiii's background service, so if the two are out of step, the older one misbehaves:

- a service that was already running keeps answering, but **does not save new chat turns** (its log says why), until it is restarted on the new version;
- a service that starts after the upgrade **runs without chat memory**, and its log says `memory db schema version … is newer than this binary supports`.

**What to do.** VS Code extension 1.0.1 works with terminal app 1.6.1 or later. Update the terminal app first (`npm install -g mochiii@latest`), run `mochiii -stop` in each folder you use it in, then update the extension and reload VS Code. There is no automatic way back to an older version after the upgrade.

## VS Code will not replace my extension

A Mochiii `.vsix` installed by hand and numbered 1.1.0 to 1.6.1 is not replaced by 1.0.1 from the Marketplace. Uninstall it first, then install from the Marketplace.

## Code search is off

**An install warned at "Downloading the code-search model".** Installs of 1.5.1 or earlier made after 19 November could not download the engine code search runs on. Update, then run:

```bash
mochiii download-model
```

**Your system is missing something code search needs.**

- On Linux, code search needs glibc 2.27 or newer (Ubuntu 18.04+, Debian 10+, RHEL 8+, Fedora 28+). On Alpine and other musl systems the build has no code search; chat and agent mode work.
- On Windows, code search needs the Microsoft Visual C++ runtime, which most PCs already have.
- Intel Macs are not supported.

To index a folder again, run `mochiii --index` in it, or **Mochiii: Index Folder for Code Search** in VS Code. See [How indexing works](/features/indexing).

## `mochiii` is not found

Open a new terminal: the one you installed from may not find the new command yet. If `mochiii` runs but says the package for your computer is not installed, run `npm install -g mochiii` again.

## Mochiii says this is not a project folder

Mochiii works on the folder it starts in. Started in your home folder or at the top of a drive, it says so and suggests a project folder. It still runs, but code search is never offered there. `cd` into the project and start it there.

## VS Code says it has no API key, with a model on my computer

With only `mochiii.apiBase` and `mochiii.model` set for a local server, extension 1.0.1 still shows "Mochiii has no API key, so the model cannot be reached and every answer will fail." Choose **Not now**: questions go to your local server without a key. See [Local models](/models/local-models).

## The model sent back an empty answer

Mochiii says `the model sent back an empty answer. Ask again, or pick another model with /model.` Do that.

## A model on my computer does not answer

- **The server stopped.** Mochiii says the model is unreachable, and adds "start it again (for Ollama: ollama serve)".
- **The model was deleted from the server.** `/connect local` lists the models the server has now.
- **It answers, but uses no tools.** In the terminal app, a model on your computer gets no tools until `/agent on`, and only if it passes the check. See [Local models](/models/local-models).
- **It is slow.** A model on a laptop's CPU can take minutes for one answer; the server is given five minutes before its first token.

## The provider is busy or limits my requests

A provider that answers "too many requests" is waited out: up to five tries over about 75 seconds, following the provider's `Retry-After`. While Mochiii waits, the terminal app shows `⏳ rate-limited — trying again in 5s` where "thinking" is. A task the provider still refuses says the rate limit is why, and keeps everything it did.

## VS Code: No answer arrived

A turn that hears nothing from the background service for 10 minutes (35 while a tool runs) ends with **No answer arrived** and **Try again**. Time waiting for your approval does not count. If it keeps happening, check the log: run **Mochiii: Show Daemon Log**.

## An MCP server will not start

See [Troubleshooting MCP](/mcp/troubleshooting).

## Where the logs are

In `~/.local/state/mochiii/logs/` (on Windows, `%LOCALAPPDATA%\mochiii\logs\`). In VS Code, **Mochiii: Show Daemon Log** opens the log. Logs can contain file paths from your project: remove anything you do not want to share before you send them.

## Still stuck

Email supportmochiii@gmail.com with your system, which client and its version, what you did, what happened, and the lines from the log. See [Beta](/getting-started/beta).
